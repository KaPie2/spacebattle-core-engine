Ядро высоконагруженного многопоточного игрового сервера космических баталий. Проект разрабатывается с применением принципов SOLID, строгой инверсии зависимостей (IoC) и многопоточной изоляции (Actor-like Pattern) в рамках курса "Объектно-ориентированный анализ и проектирование" (4-5 семестр).

## Архитектурные принципы
- **IoC-First:** Полный отказ от оператора `new` для бизнес-логики.
- **Code Generation:** Автоматическая генерация классов-адаптеров "на лету" через Reflection Engine.
- **Thread Confinement:** Выполнение игровых сессий в строго изолированных потоках без применения блокировок `lock`.
- **$O(1)$ Operations:** Остановка операций и проверка коллизий за гарантированное константное время.

## Структура кода

| Папка в `SpaceBattle.Lib` | Что сюда добавлять |
| --- | --- |
| `CodeGeneration` | Генерацию и компиляцию адаптеров, шаблон и фабрики, автоинъекцию команд. |
| `Commands` | Контракты команд, команды движения и поворота, макрокоманды и их стратегии. |
| `GameObjects` | Игровые объекты и контракты их свойств, например `IMovingObject` и `IRotatingObject`. |
| `Geometry` | Типы для геометрических расчётов, например `NVector` и `Angle`. |
| `IoC` | Общие регистрации и инфраструктуру IoC. Регистрации, тесно связанные с одним модулем, хранятся рядом с ним. |
| `Threading` | Очереди, отправку команд между потоками и управление жизненным циклом игровых потоков. |

Тесты в `SpaceBattle.Lib.Tests` повторяют названия папок библиотеки. Для типов библиотеки используйте пространство имён `SpaceBattle.Lib`, для тестов — `SpaceBattle.Lib.Tests`.

### Как обновить рабочую ветку

1. Сохраните свои изменения в коммите. После слияния переноса папок в `main` выполните в рабочей ветке `git fetch origin` и `git merge origin/main`.
2. Проверьте файлы, которые появились только в вашей ветке. Если они остались в корне проекта, перенесите их и соответствующие тесты в папки по таблице. Зафиксируйте перенос отдельным коммитом, чтобы в ревью было проще увидеть изменения логики.
3. Выполните `dotnet test SpaceBattle.sln` и проверьте вкладку **Files changed** в своём PR.
